# Mode A デモアプリ

Nano API Proxy の **モードA（ブラウザ内 `fetch` 横取り）** を手元で確認するためだけの、テスト用デモアプリです。ビルド不要・依存ライブラリなしの素のHTML/JS/CSSです。

## 使い方

1. このリポジトリを Chrome に拡張機能として読み込む（`chrome://extensions` → デベロッパーモード → パッケージ化されていない拡張機能を読み込む → リポジトリのルートを選択）。
2. サイドパネルで Built-in AI が `AVAILABLE` になっていることを確認し、Intercept が `ON` になっていることを確認する。
3. このディレクトリを `http://localhost` または `http://127.0.0.1` で配信する（`file://` では拡張機能の対象オリジンにマッチしないので動きません）。

   ```bash
   cd demo
   python3 -m http.server 5500
   ```

4. ブラウザで `http://127.0.0.1:5500/` を開く。
5. Vendor（OpenAI / Anthropic / Gemini）と Streaming の有無を選び、メッセージを送信する。

## 何をしているか

送信ボタンを押すと、実在する各社のホスト名（`api.openai.com` など）に向けて素の `fetch()` を実行します。拡張機能の Intercept が有効なら、この `fetch` は実際のネットワークに出る前に拡張機能側で捕捉され、Gemini Nano の応答に差し替えられます。

- **拡張機能が正しく動いている場合**：ダミーの `Authorization: Bearer dummy` などを使っていても、Gemini Nano の応答がストリーミング（またはJSON一括）で返ってきます。
- **Intercept が OFF、または拡張機能が入っていない場合**：本物の外部ホストへの通信になるため、無効なAPIキーによる401エラーやCORSエラーなど、通常のネットワークエラーになります。これは「横取りされていない」ことの分かりやすいシグナルとして使えます。

画面下部の「直近のリクエスト/レスポンス (raw)」を開くと、実際に送信したリクエストボディと、返ってきた生のレスポンス（SSEチャンクまたはJSON）を確認できます。
